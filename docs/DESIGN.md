# 小闫个人官网设计系统（历史基线）

> 当前升级采用 [Celestial Atlas / 个人星图](CELESTIAL_REDESIGN.md)，实现入口为 `app/universe-system.css`。下文保留原工业现场手册的设计背景；其中关于禁止星海、持续动效等旧约束已由本次明确的天文科技、动画与生活主题需求替代。内容真实性、原生导航、响应式和可访问性约束继续适用。

> 设计主题：**Industrial Field Manual / 工业研究现场手册**  
> 当前实现基准：`app/design-system.css`。本文说明如何延续现有视觉与交互，若文档与代码不一致，以已验证的 CSS token 和组件行为为准。

## 1. 设计意图

网站服务于导师、科研合作者、技术同行与招聘者。第一屏先说明“研究什么、如何判断、证据在哪里”，随后把访问者引向独立栏目和详情页，而不是在首页展开全部资料。

核心视觉概念是 **Material Evidence Stage**：冷静的实验室纸白作为底色，深海军蓝承载严肃内容，钴蓝负责操作与导航，青绿代表过程与可信边界，铜色只用于材料和编号提示。图片是研究场景证据，不是装饰。

品牌签名是四阶段过程登记线：

`观测 → 建模 → 优化 → 审查`

它在首页完整出现，在栏目和详情页中只以章节编号、细线或阶段标记回响。不得把它扩展成无真实数据支撑的仪表盘、实时状态或假图表。

### 必须坚持

- 直接、准确、克制，优先呈现问题、方法、证据边界与下一层入口。
- 主研究站不使用霓虹 HUD、紫色渐变、玻璃拟态或通用 Bento 卡片墙。动画观测站采用既定的局部深色编辑风格，允许使用克制的星海与铜色轨迹，但必须服务于真实年份和内容索引。
- 不为视觉效果虚构论文、奖项、机构、规模、指标、日期或项目成效。
- 页面之间可以有节奏差异，但必须共享同一组颜色、字体、边线、间距和状态语言。

## 2. 基础 Tokens

### 色彩

| Token | 值 | 用途 |
|---|---:|---|
| `--paper` | `#f4f7fb` | 全站冷白底色 |
| `--paper-warm` | `#f7f5f0` | 待补资料、说明性区域 |
| `--surface` | `#ffffff` | 记录带、列表悬停、内容层 |
| `--surface-soft` | `#eaf0f7` | 当前项、轻交互反馈 |
| `--surface-hover` | `#dbe6f2` | 链接与台账行的明确悬停反馈 |
| `--ink` / `--navy` | `#07162e` | 正文标题、深色舞台、页脚 |
| `--ink-soft` | `#26364f` | 高可读正文 |
| `--muted` | `#52617a` | 说明、元信息、次级文字 |
| `--line` | `#c9d3e1` | 常规分隔线 |
| `--line-strong` | `#9eacc0` | 结构边界、重要分隔线 |
| `--blue` | `#1457d9` | 主操作、当前导航、链接 |
| `--blue-dark` | `#0c3faa` | 主操作悬停、强调状态 |
| `--teal` | `#087d7a` | 过程、审查、可信主题 |
| `--teal-light` | `#bde4de` | 深色背景上的高亮 |
| `--copper` | `#a94d28` | 序号、材料提示、待核实边界 |
| `--copper-light` | `#e6b09b` | 铜色的低权重延展 |
| `--success` | `#176b51` | 已核实状态 |
| `--focus` / `--focus-on-dark` | `#0a4ed1` / `#b9d1ff` | 浅色与深色表面的键盘焦点环 |

颜色分工不可互换：蓝色表示“可行动/当前位置”，铜色表示“索引/材料/资料边界”，青绿表示“过程/可信性”。任何状态不能只靠颜色表达，必须同时有文字或结构标记。

### 字体与排版

```css
--font-sans: ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI Variable Text", "Noto Sans SC", "PingFang SC", "Microsoft YaHei UI", sans-serif;
--font-display: ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI Variable Display", "Noto Sans SC", "PingFang SC", "Microsoft YaHei UI", sans-serif;
--font-mono: "Cascadia Mono", "SFMono-Regular", Consolas, monospace;
```

- 中文正文用 `--font-sans`，标题用 `--font-display`；编号、章节码、短英文标签用 `--font-mono`。
- 正文基准 `16px / 1.65`；长文建议 `16px / 1.9`，最大行宽 `--reading: 38rem`（约 608px）。
- 首页主标题 `clamp(58px, 7.2vw, 94px)`；栏目主标题 `clamp(48px, 6.8vw, 78px)`；区块标题 `clamp(38px, 5.2vw, 64px)`。
- 中文标题保持 `letter-spacing: 0`；只有纯拉丁章节码、数字与短英文标签允许收紧字距。
- 标题字重只使用 `700` 与 `800` 两档，避免静态中文字体把多个中间字重映射成同一档。
- 辅助文字原则上不小于 `12px`。英文微标签只写短词或代码，不用大段全大写英文替代中文信息。
- 标题使用平衡换行，正文按自然语义换行；不要用 `<br>` 强行制造跨设备一致的正文断行。

### 宽度、网格与间距

| Token / 规则 | 值 |
|---|---:|
| 内容最大宽度 | `--max: 1200px` |
| 长文最大宽度 | `--reading: 38rem` |
| 页面边距 | `--gutter: clamp(20px, 4vw, 48px)` |
| 桌面页头 | `72px` |
| 移动页头 | `68px` |
| 常规区块纵向留白 | `104px` |
| 移动区块纵向留白 | `76–80px` |

- 首页首屏使用 12 列网格；文字占左侧约 7 列，证据图跨右侧约 7 列并产生克制叠置。
- 栏目入口优先采用双栏开放网格、台账行或时间轴，不套统一卡片外壳。
- 间距以 4/8px 为基础，优先从 `8、12、16、20、24、28、32、36、44、48、56、64、80、96、104` 取值。
- 用空白和 1px 边线表达层级。不要通过不断增加背景块和阴影制造分组。

### 圆角与阴影

```css
--radius-xs: 4px;
--radius-sm: 8px;
--radius-md: 14px;
--radius-lg: 24px;
--shadow-sm: 0 8px 24px rgba(7, 22, 46, .07);
--shadow-md: 0 22px 60px rgba(7, 22, 46, .13);
```

- 按钮、品牌符号、图注以 `4px` 为主；大圆角仅用于确有容器意义的独立对象。
- 阴影仅用于导航浮层、证据图舞台等真正高于页面的层级；普通内容块使用边线。

### 动效

```css
--ease-out: cubic-bezier(.22, 1, .36, 1);
--ease-standard: cubic-bezier(.4, 0, .2, 1);
--motion-fast: 160ms;
--motion-base: 280ms;
--motion-slow: 520ms;
```

- `160ms`：颜色、边框、轻反馈；`240–280ms`：页面淡入、导航与下划线；`520ms`：首屏证据图与过程线编排。
- 图片悬停最多缩放至 `1.025`，按钮最多上移 `2px`；不使用持续漂浮、弹簧抖动或大面积视差。
- 页面切换只做约 `240ms` 的透明度淡入；首页证据图轻入，过程线从左向右绘制。
- 项目详情可使用一次性 `IntersectionObserver` 显现内容段，只改变透明度与纵向位移，并在无脚本或减少动态效果时保持内容直接可见。
- `prefers-reduced-motion: reduce` 下必须取消页面、图片、过程线和导航动画，并禁用悬停位移。

## 3. 页面体系

### 首页：概览与分流

首页的固定顺序为：

1. 研究身份、核心命题、两个主入口与一张证据图。
2. `观测 → 建模 → 优化 → 审查` 四阶段过程线。
3. 四项已知事实带，不放未经核实的数量指标。
4. 一项带图重点案例和一项次级案例。
5. 知识库、随想、生活记录三个入口。
6. 联系与合作收束区。

首页只回答“我是谁、研究什么、从哪里继续看”，不复制栏目页详情。重点案例使用整行图文构图；次级案例使用台账行，避免卡片堆叠。

### 栏目页：`PageHero` + 内容专用结构

栏目页统一使用 `PageHero`，包含面包屑、章节代码、中文眉题、一个 `h1`、简述与可选侧栏。`tone="dark"` 仅用于需要深色研究舞台的栏目，不应成为默认。

正文按内容选择结构：

- 研究/总览：`.portal-grid` 或 `.system-route-track`。
- 项目：`.project-index-list`，按编号、题目、摘要、标签展开。
- 论文/成果/文章：`.record-ledger-list`、`.publication-ledger` 或 `.editorial-list`。
- 教育/实践/履历：`.timeline-node` 时间轴。
- 技术能力：`.capability-matrix`，按技术层和使用边界组织。
- 知识库：`.knowledge-index-grid`，强调主题索引而非“文章封面”。
- 生活：`.life-editorial-grid`，允许更有编辑感的色块，但仍遵守全站色彩与事实规则。
- 动画分站：`.animation-site-shell` + 年份轨道 + 开放式影评台账；使用深海军蓝、低饱和钴蓝和铜色，并通过二级导航进入年度推荐、影评档案、番剧总表与观看时间线。
- 个人介绍：叙事正文、事实表和研究原则分区组合。

一个页面只选一种主结构，其他结构只能作为辅层。不要把所有内容重新包装成相同卡片。

### 详情页：三种模板

1. **项目案例页**：深色 `.case-hero` + 事实元信息 + 目录侧栏 + 问题/方法/验证/局限内容段 + 相关入口。项目结论必须与现有证据强度一致。
2. **通用详情页**：`.detail-shell-hero` + `.detail-shell-body` + `.detail-navigation`，适用于论文、教育、经历、荣誉、随想和生活条目。
3. **技术/知识详情页**：技术页使用 `.skill-detail-*` 表达能力层级和审查清单；知识页使用 `.note-detail-*` 表达状态、正文和免责声明。

详情正文维持 `38rem` 阅读宽度，事实侧栏和上一篇/下一篇导航可以突破正文宽度，但不能压缩正文。每页只有一个主 `h1`，标题层级顺序递进。

## 4. 导航与响应式交互

### 桌面端（`min-width: 1021px`）

- 栏目名称本身是可导航链接，旁边独立按钮只负责展开/收起 Mega Navigation。
- 章节码与导航层级一致：一级栏目使用 `01–06`，子页使用 `A1 / R1 / O1 / J1 / I1 / L1` 等组内编号；不得另起一套全站流水号。
- `ArrowDown` 可展开并把焦点移入浮层；`Escape` 关闭并返回原按钮；点击页头外关闭。
- 当前页使用 `aria-current="page"`，当前详情所属栏目使用 `aria-current="location"`，文字分别显示“当前/所在”。
- Mega Navigation 是清晰的栏目索引，不允许加入无对应页面的装饰按钮。

### 平板与移动端（`max-width: 1020px`）

- 菜单为模态抽屉：打开后锁定 body 滚动、背景设为 `inert`、焦点进入关闭按钮，并在抽屉内循环。
- `Escape`、关闭按钮、背景遮罩和完成导航都应关闭菜单并恢复菜单按钮焦点。
- 栏目名称仍直接进入栏目页；`+` 按钮只控制子菜单展开，二者不能合并为一个不明确点击区。
- `760px` 以下抽屉占满宽度，隐藏遮罩；内容改为单列并保持至少 `16px` 正文字号。
- `460px` 以下进一步把过程线、事实带、站点地图和窄列表改为单列。

断点 `1021px` 是现有交互状态机契约。修改响应式边界时必须同步检查焦点转移和菜单状态，不能只改 CSS。

## 5. 图片规范

- 优先使用研究对象、设备、材料和过程细节的纪实构图；拒绝抽象 AI 大脑、代码雨、霓虹实验室等通用科技图。
- 当前 AI 生成图片必须在图注中明确写明“AI 生成图像，仅作场景表达”。真实摄影替换后再移除此声明。
- 动画观测站的纯装饰星海背景为 AI 生成资产，不表达作品或观看数据；具体作品必须使用真实海报，且素材来源记录在 `docs/animation/poster-sources.json`。
- 生产资源优先使用 WebP；必须写 `width`、`height` 和准确 `alt`，避免布局偏移。
- 首屏主图可用 `fetchPriority="high"`；非首屏图使用 `loading="lazy"`。
- `alt` 描述图中可见对象，不重复图注，不把图片解读成未经证实的实验结果。
- 图片调色保持冷白、铜、蓝绿电解液与深海军蓝的材料关系；不叠加降低可读性的彩色滤镜。
- 首页主图允许单次切角签名；后续图片以规则裁切为主，不重复制造多个异形轮廓。

## 6. 内容真实性与资料需求

内容状态使用三类低权重标识：

- `verified`：有现有资料支持的个人事实。
- `topic`：真实研究方向或计划中的主题，不代表已经取得结果。
- `placeholder`：学校、导师、日期、DOI、奖项证明、外链、量化成效等资料尚未完整。

资料需求必须使用 `.placeholder-panel`、`.content-placeholder-note` 或 `.empty-state`，直接写明完成该部分所需的具体字段，例如学校、起止时间、DOI、证明链接或评价结果。不得用假邮箱、假 DOI、虚构奖项、示例指标或“Lorem ipsum”撑版。资料需求区域使用暖白底和铜色左边线，视觉权重应低于已核实内容。

新增资料时先更新数据源，再由页面模板渲染；不要把事实散落硬编码在多个页面。任何“提升、领先、最佳、显著”等判断都需要可核实证据。

## 7. 可访问性与技术契约

- 目标为 WCAG 2.2 AA。文字与背景保持足够对比，交互目标在可行时至少 `44 × 44px`。
- 保留跳转链接与 `main#main-content`；每页保持语义化 `header/nav/main/section/footer`。
- 所有交互都必须可由键盘完成，使用 `2px` 高对比焦点环与 `4px` 外偏移；深色表面切换为专用浅色焦点 token，不能用 `outline: none` 隐藏焦点。
- 图标若无独立语义，设置 `aria-hidden="true"`；按钮必须有可理解的 `aria-label`。
- 展开按钮同步 `aria-expanded` 和 `aria-controls`；模态菜单同步 `role="dialog"`、`aria-modal`、`aria-hidden` 与 `inert`。
- 页面意义、状态和当前位置不能只靠颜色、悬停或动画表达。
- 支持 `prefers-reduced-motion`、打印样式、安全区和最小 `320px` 视口。

### Vinext 导航硬约束

全站内部页面跳转必须使用原生 `<a href="…">`，并在现有位置保留 `data-navigation="document"`。这是 Vinext 生产环境兼容性要求，**禁止改回 `next/link`**。新增链接必须指向实际存在的路由；提交前应运行内部链接完整性测试。

## 8. 扩展组件指南

新增页面或模块时按以下顺序选择，不要先创建新视觉语言：

1. 使用 `PageHero` 建立栏目身份，或使用现有详情 Hero 类族建立条目身份。
2. 从开放网格、台账行、时间轴、矩阵、长文五种结构中选择最符合内容的一种。
3. 复用 `.section-shell`、`.section-kicker`、`.primary-action`、`.text-link`、`.status-badge` 和 `.placeholder-panel`。
4. 仅当现有结构无法表达新的信息关系时才新增组件；新增 token 前先证明现有 token 不足。

### 组件书写约定

- 组件名称描述信息结构，如 `EvidenceLedger`、`MethodTimeline`，避免 `PrettyCard`、`GlassPanel` 等视觉化命名。
- 交互组件维护默认、hover、focus-visible、active、disabled/empty 和 reduced-motion 状态。
- 链接负责导航，按钮负责改变当前界面状态；不得用可点击 `div`。
- 列表项整体可点击时只保留一个主链接，避免嵌套交互元素。
- 新增深色区域时复用 `--navy` 与现有浅色文字组合；新增强调色需先完成对比与品牌必要性审查。
- 新增模块同时检查桌面、`1020px`、`760px`、`460px` 和 `320px`，并验证横向溢出、长中文、键盘顺序和返回路径。

### 发布前最低检查

- 所有可见按钮和链接都有实际响应，栏目页与详情页均可到达。
- 首页、栏目页、详情页各抽查桌面和移动截图；无横向滚动条、遮挡、截断或异常小字。
- Mega Navigation、移动抽屉、Escape、焦点恢复、背景关闭、断点切换全部通过。
- `prefers-reduced-motion` 生效；图片尺寸、alt、加载策略与 AI 图注正确。
- 无未经核实的强结论或伪数据；资料需求明确且低权重。
- lint、路由/内部链接测试和生产构建通过后再部署。
